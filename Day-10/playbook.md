# Executive Playbook: Designing Lean Workplans

## Purpose
Give a repeatable, 60-minute routine for **lean analytical workplans** that you can run on any project.

## Core idea
A lean workplan translates issue-tree branches into a hypothesis-to-analysis chain with a data source, owner and deadline. Effort caps prevent boiling the ocean: any analysis longer than five days is split or cut.

## Procedure
### Step 1
Take each prioritised branch and restate it as a hypothesis.

**Deliverable:** one written paragraph or table that proves this step is complete.

### Step 2
Define the minimum analysis that would test it.

**Deliverable:** one written paragraph or table that proves this step is complete.

### Step 3
Identify the data source and any access risk.

**Deliverable:** one written paragraph or table that proves this step is complete.

### Step 4
Assign one owner and a deadline.

**Deliverable:** one written paragraph or table that proves this step is complete.

### Step 5
Cap effort at five days per analysis and review weekly.

**Deliverable:** one written paragraph or table that proves this step is complete.

## Watch-outs
- Analyses without a hypothesis
- Owners with more than 40 percent of effort

## Worked example
**SaaS churn diagnosis workplan.** A six-row workplan covered seat counts, onboarding drop-off, pricing, support SLAs, competitor parity and journey mapping. The validator flagged one row with no owner, one overdue, and two over-scoped analyses, which the team split or dropped before work began.

## Quality bar
- Every row has hypothesis, analysis, source, owner and date
- No analysis exceeds five days
- Overdue items are visible
- The plan fits the engagement timeline
